# 项目基线与执行大纲 (PROJECT BRIEF)

## 一、项目身份与元信息
- **网站名称**：网络诊断实验室 (netzhenduan.cc)
- **主域名**：`https://netzhenduan.cc`
- **定位**：以“不会用、连不上、速度慢、网页打不开”等真实故障排障为搜索入口，结合在线交互探针与网络可观测性，引导用户完成故障自检、服务状态核验与高可用专线机场选型。
- **技术栈**：VitePress 1.6.4 + Vue 3 交互组件 + Local Search (MiniSearch) + 自动 Sitemap + Apache 静态部署 (`.htaccess` 规范化重写与 AFF 安全跳转)。
- **视觉系统**：Dark Network Observatory（深海军蓝 `#090d16`、状态指示灯、网格架构、技术等宽字体、无浮夸营销感）。

## 二、确认的一级导航架构 (8大核心栏目)
1. 首页 (`/`)
2. 科学上网问题 (`/issues/`)
3. 梯子连不上 (`/connection/`)
4. 客户端故障 (`/clients/`)
5. 机场订阅问题 (`/subscription/`)
6. 网络诊断实验室 (`/diagnostics/`)
7. 使用教程 (`/tutorials/`)
8. 机场推荐与品牌库 (`/airports/`)
9. 免费机场与应急替代 (`/free/`)

## 三、层级与容量计算标准 (依据总指令第二条)
- **一级大专题 (N)**：8 个（不含首页）。
- **二级专题 (S)**：8N～12N，本项目基准为 8 × 8 = 64 个二级专题。
- **三级集群 (C)**：2S，即 64 × 2 = 128 个三级内容集群。
- **独立文章 (A)**：8C～12C，即 128 × 8 = 1024 篇独立文章（基准目标）。
- **页面总数 (P)**：1 + N + S + C + A = 1 + 8 + 64 + 128 + 1024 = 1,225 篇。
- **篇幅指标**：正式长文与核心入口目标为 10,000～15,000 汉字，以可见主体汉字数为准；必须覆盖 12 大必查模块（答案摘要、对象概念、指标标准、参数对比表、ASCII 决策树、原理解析、场景判断、实操验证、案例分析、FAQ、转化与下一步、来源与维护）。

## 四、真实缺口与阻塞登记 (Gap Analysis)
1. **全量千篇规模与上下文容量限制**：受限于大模型上下文窗口与单次执行步长，必须严格采用“分阶段、分批次、落盘存档、持续推进”的施工规则。
2. **狭窄排障主题与万字篇幅张力**：针对单一小错误（如单个端口修改），若强行扩写至万字容易导致同义反复。执行策略是**以深层网络协议机制、操作系统底层网络栈、抓包复现、防御式配置、同类故障关联对比与真实故障日志排查**进行纵深展开；确实资料不足的小问题登记为“篇幅目标与搜索意图冲突”，优先保证信息质量。
3. **数据真实性原则**：42 家机场品牌严格基于用户提供的 `42家机场品牌清单.txt` 原文核验，严禁捏造价格、测速与解锁状态，未知项统一标注“待核实”。
