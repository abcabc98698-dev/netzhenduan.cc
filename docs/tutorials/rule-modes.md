# 规则模式与全局模式原理深度解析：如何科学合理分流？

在所有现代科学上网客户端（无论是基于 Rust / Tauri 开发的 Clash Verge Rev、基于 .NET 开发的 v2rayN、基于 Go 语言内核的 sing-box，还是 iOS 生态中的 Shadowrocket 小火箭）的主控制界面中，最显眼也是最频繁被用户点击切换的核心功能模块，莫过于**分流模式（Routing / Outbound Mode）**选项栏。

然而，在广大新手用户的实际日常使用中，最常犯也是最具破坏性的典型误区莫过于：**为了“确保彻底翻出去”、或者在遇到某一个网页打不开时，图省事顺手将分流模式勾选为「Global（全局模式）」**。

随之而来的却是一系列令人猝不及防且难以解释的严重次生灾害：
- 微信、企业微信或钉钉频繁弹出安全警告：“检测到异常登录环境，请重新进行实名验证与人脸识别”，甚至触发支付功能临时风控冻结；
- 打开淘宝、京东、美团、网易云音乐等国内头部应用时，页面加载陷入长时间卡顿，高清商品图片半天显示为空白占位符，网易云音乐直接弹窗提示“您所在地区由于版权限制无法收听”；
- 刚刚斥资购买的 100GB 机场高速商业专线月度配额，电脑在后台开着挂机仅一下午，看了几集国内爱奇艺高清电视剧或后台下载了几个国内客户端补丁，数万元采购级的高速流量瞬间被彻底耗尽清零！

网络分流绝不是一个简单的“全局翻墙开关”，而是一个基于网络五元组特征（源 IP、源端口、目的 IP、目的端口、传输层协议）、域名多叉树倒排索引、地理 IP（GeoIP）高维掩码计算以及系统进程签名的高性能软路由调度中枢。

本手册为您提供标准工业级的 12 大深度解析模块。我们将从底层路由转发数学模型、五阶段报文匹配流水线、四大核心分流模式横评，直到企业级 YAML 规则集实战，带您彻底掌握科学合理分流的工程内幕。

## 模块一：分流模式核心定义与底层网络开销

在展开具体的规则配置前，网络工程师必须首先在传输层工程维度解答一个本质问题：**为什么科学上网必须依靠智能分流，而绝不能一刀切走全局代理？**

```
+─────────────────────────────────────────────────────────────────────────────+
|                         分流模式底层网络开销与路径对比                      |
+─────────────────────────────────────────────────────────────────────────────+
| [场景 A：全局模式 (Global)] ── 任何流量无条件绕道境外专线                    |
|   本机 ───(国内网段)──► 跨境 IEPL 专线 ──► 香港落地机 ──► 绕回中国大陆电信服务器   |
|   * 结果：原本仅需 5ms 的本地访问，被硬生生拉长至 80ms+，且占用双向跨境昂贵带宽|
+─────────────────────────────────────────────────────────────────────────────+
| [场景 B：规则分流模式 (Rule)] ── 智能精准识别，各走各路                      |
|   ├─► 海外流量 (Google/GitHub/YouTube) ──► 加密专线隧道 ──► 境外落地机 (极速) |
|   └─► 国内流量 (Bilibili/微信/百度/网银) ──► 本地物理网关 ──► 直连服务器 (5ms秒开)|
|   * 结果：国内体验与不挂代理完全一致，专线流量 100% 用在刀刃上！             |
+─────────────────────────────────────────────────────────────────────────────+
```

### 三大底层网络开销指标深度量化

1. **往返往返时间（RTT）成倍激增与网络发夹（Hairpinning）效应**：
   - 当你在上海访问位于杭州的阿里云服务器时，在本地物理网络直连下，往返延迟仅有 5~8 毫秒。但在全局模式下，数据包必须先经过跨境 IEPL 专线送达香港或日本落地机房，再由境外落地机跨洋发起反向请求穿透回杭州服务器。端到端物理链路距离从 200 公里骤增至数千公里，TCP 握手延迟直接飙升至 80~150 毫秒以上。
2. **商业内网专线昂贵带宽的无效损耗**：
   - 优质机场租用的跨境 IEPL / IPLC 纯内网物理专线，其按带宽计费的成本极其高昂（单 Gbps 物理专线月租常达数万元人民币）。将国内的高吞吐量流媒体（如抖音、B站 4K 视频）或 P2P 下载流量送入跨境专线，是对高价值低延迟网络资源的毁灭性浪费。
3. **企业与金融级风控信任分（Fraud Risk Score）雪崩**：
   - 微信支付、支付宝、各家商业银行 App 以及办公协作系统（如飞书、企业微信），均部署了基于 IP 属地一致性与自治系统编号（ASN）的反欺诈模型。当系统检测到用户的客户端 IP 突然从常规家庭宽带（AS4134 中国电信）突变为境外知名托管机房（如 AS13335 Cloudflare 或海外主机商），风控引擎会立即认定该连接为恶意爬虫、撞库黑客或账号被盗，从而触发人脸验证、强制登出或资金冻结。

## 模块二：分流引擎架构与报文匹配流水线

在 Clash / Mihomo 等现代化代理核心中，每一个网络数据包在流经分流模块时，都会严格遵循一套标准化的**五阶段树状流水线（Packet Processing Pipeline）**。

理解这一顺序，是排除“为什么明明加了直连规则却还是走了代理”的核心基石：

```mermaid
flowchart TD
    InPacket[应用程序发起网络请求: 目标域名或 IP:Port] --> Step1{阶段 1: 命中 DOMAIN 规则?}
    
    Step1 -->|命中完全匹配| Action1[执行策略: PROXY 节点组]
    Step1 -->|未命中| Step2{阶段 2: 命中 DOMAIN-SUFFIX 后缀?}

    Step2 -->|命中 (如 *.bilibili.com)| Action2[执行策略: DIRECT 直连]
    Step2 -->|未命中| Step3{阶段 3: 命中 DOMAIN-KEYWORD 关键字?}

    Step3 -->|命中 (如 *steam*)| Action3[执行策略: GAME 专线策略组]
    Step3 -->|未命中| Step4{阶段 4: 命中 IP-CIDR / GEOIP?}

    Step4 -->|命中 (如 GEOIP,CN 国内IP)| Action4[执行策略: DIRECT 直连]
    Step4 -->|未命中| Step5[阶段 5: 命中 MATCH / FINAL 最终兜底规则]
    Step5 --> Action5[执行最终默认策略: 通常为 PROXY]
```

### 五大匹配规则类型技术特性表

| 规则类型 (Rule Type) | 匹配对象与语法示例 | 匹配优先级 | 底层算法与资源开销 | 典型适用场景 |
|---|---|---|---|---|
| **DOMAIN** | `DOMAIN,api.openai.com,ChatGPT` | 最高 (第 1 阶) | 字符串精确 Hash 查表 (O(1) 复杂度) | 精确到单台主机的绝对匹配，不受二级域名干扰 |
| **DOMAIN-SUFFIX** | `DOMAIN-SUFFIX,apple.com,DIRECT` | 极高 (第 2 阶) | 倒排后缀多叉树检索 (Trie Tree) | 匹配该主域名及其所有子域名（推荐主力使用） |
| **DOMAIN-KEYWORD** | `DOMAIN-KEYWORD,google,PROXY` | 高 (第 3 阶) | Aho-Corasick 多模式字符匹配 | 泛匹配包含特定关键词的所有域名（注意防止误伤） |
| **GEOIP** | `GEOIP,CN,DIRECT` | 中等 (第 4 阶) | MaxMind 二叉树 IP 掩码区间匹配 | 依靠内置 GeoIP 数据库，按目标服务器所属国家分流 |
| **MATCH / FINAL** | `MATCH,PROXY` | 最低 (兜底) | 无须匹配，直接收容所有未命中流量 | 上述规则均未命中时的最终默认归宿 |

## 模块三：四大主流分流模式深度对比

下表将各大客户端支持的四大主流分流模式进行了全方位的工程度量对比：

| 分流模式名称 | 核心调度逻辑 | 适用人群与业务场景 | 优缺点深度评估 |
|---|---|---|---|
| **Rule (规则模式)**<br>【强烈推荐】 | 严格按照配置文件中的 rules 规则链自上而下匹配，命中则走对应策略组，未命中由 MATCH 规则收敛 | **99% 日常场景首选**。适合所有日常办公、海外追剧、跨国科研与程序开发用户 | **体验完美平衡**。国内服务纯净直连、海外资源高速加密、恶意广告自动屏蔽，无感透明 |
| **Global (全局模式)** | 彻底忽略配置文件中的所有分流规则，强制所有进出客户端的流量全部无条件发往单一指定代理节点 | 仅限临时调试：访问冷门境外小众站点未被规则库收录、测试单节点绝对连通性 | **缺陷极大**。国内应用极慢、流量飞速耗尽、微信容易被风控封号，严禁长期常驻 |
| **Direct (直连模式)** | 彻底忽略配置文件中的所有代理策略，强制所有网络流量无条件从本地物理网卡发出 | 仅限网络排错：怀疑代理软件导致网络异常时，切换此模式排查本地宽带物理连通性 | 相当于“临时在逻辑上关闭代理客户端”，此时海外受限网站完全无法打开 |
| **Script (脚本模式)** | 允许用户编写 JavaScript 或 Python 逻辑，基于时间段、网络延迟、源进程动态判定路由 | 仅限骨灰级网络极客：实现多宽带并发负载均衡、特定程序按时段智能走不同节点 | 配置与维护门槛极高，语法错误容易引发核心静默闪退，普通用户无须折腾 |

## 模块四：为什么全局模式会导致国内应用变慢与风控？

理解全局模式引发灾难的技术机理：

```
+─────────────────────────────────────────────────────────────────────────────+
|                         全局模式引发国内访问卡顿的四大机理                  |
+─────────────────────────────────────────────────────────────────────────────+
| 机理 1：物理路径成倍拉长 (Hairpin Routing)                                  |
|   你访问深圳的腾讯服务器，数据包先跨洋飞到美国西海岸机房，再由美国机房跨洋发回深圳|
|   往返延迟直接由 8ms 暴增至 300ms 以上，TCP 握手慢如蜗牛                    |
+─────────────────────────────────────────────────────────────────────────────+
| 机理 2：CDN 调度严重错乱 (CDN Geolocation Misrouting)                       |
|   国内大型应用（如哔哩哔哩、抖音、爱奇艺）依靠 DNS 判定用户归属地并下发就近 CDN |
|   全局模式下，国内平台识别你为境外用户，下发海外 CDN 节点，导致下载带宽被掐死|
+─────────────────────────────────────────────────────────────────────────────+
| 机理 3：版权地区墙反向阻断 (Reverse Geo-Blocking)                           |
|   国内音乐与视频平台（如网易云音乐、腾讯视频）仅限中国大陆 IP 播放             |
|   全局模式下节点显示为境外，直接触发反向版权墙拦截，提示“地区受限”无法播放    |
+─────────────────────────────────────────────────────────────────────────────+
| 机理 4：风控模型判定异地异常 (Security Risk Mitigation)                      |
|   微信、支付宝、网银对境外数据中心机房 IP 具有极高警惕性，极易触发人脸识别或冻结|
+─────────────────────────────────────────────────────────────────────────────+
```

## 模块五：Rule Provider 外部规则集机制与自动更新

在早期的 Clash 时代，所有分流规则必须硬编码写在配置文件的 `rules:` 模块中。如果需要更新某个网站的域名，必须重新下载整份配置文件。

新一代 **Mihomo / Clash Verge Rev** 引入了工业级的 **Rule Provider（规则集提供商）** 机制：

### 1. 规则集解耦架构与三大行为模式 (Behavior)
在传统静态配置模式下，如果需要维护成千上万条域名规则，配置文件将庞大臃肿且极难维护。新一代 Mihomo / Clash Verge Rev 引入的 Rule Provider 机制，将规则集解耦为外部动态数据源，并支持三种核心行为模式（Behavior）：
- **`behavior: domain`（纯域名匹配树）**：专门用于高效存储海量纯域名或泛域名列表。内核会在底层自动将其构建为倒排前缀树（Trie Tree），内存占用极低，检索速度达到纳秒级；
- **`behavior: ipcidr`（IP 掩码区间）**：专门用于存储大量的 IP 网段（例如国内全量 IPv4/IPv6 广播段）。内核使用基数树（Radix Tree）进行最长前缀匹配（LPM）；
- **`behavior: classical`（经典混合语法）**：允许在规则集文件中混用 `DOMAIN`、`DOMAIN-SUFFIX`、`IP-CIDR`、`PORT` 等复合规则，适用于需要对特定服务（如 Netflix、Spotify）进行多维度立体分流的场景。

```yaml
# 生产级 Rule Provider 配置范式
rule-providers:
  china-domain:
    type: http
    behavior: domain
    url: "https://testingcf.jsdelivr.net/gh/Loyalsoldier/clash-rules@release/direct.txt"
    path: ./ruleset/china-domain.yaml
    interval: 86400  # 每 24 小时自动更新一次规则库

  gfw-domain:
    type: http
    behavior: domain
    url: "https://testingcf.jsdelivr.net/gh/Loyalsoldier/clash-rules@release/gfw.txt"
    path: ./ruleset/gfw-domain.yaml
    interval: 86400

  custom-composite:
    type: http
    behavior: classical
    url: "https://raw.githubusercontent.com/user/rules/main/composite.yaml"
    path: ./ruleset/custom-composite.yaml
    interval: 43200
```

### 2. GeoSite 与 GeoIP 数据库的技术代差
许多用户常分不清 `GeoSite` 与 `GeoIP` 的本质区别：
- **`GeoIP` (地理 IP 数据库)**：仅根据 IP 地址的地理注册信息进行匹配（例如 `GEOIP,CN` 匹配中国大陆公网 IP）。它的缺点是必须先知道目标 IP，容易受到 DNS 污染的误导；
- **`GeoSite` (域名分类数据库)**：直接在应用层针对域名进行语义级聚合。例如 `GEOSITE,google` 自动包含了 Google 旗下的全球数百个主域名与 CDN 域名；`GEOSITE,category-ads-all` 则收录了全球数万个广告与遥测追踪域名。
在现代配置中，**强烈推荐优先使用 `GEOSITE` 进行域名分流，仅使用 `GEOIP` 作为无域名 raw-IP 流量的兜底分流**，这是保障分流极致精准、彻底告别本地 DNS 污染的关键策略。

## 模块六：DNS 解析分流与 Fake-IP 在分流中的关键角色

很多用户感到困惑：“我的规则里明明写了 `GEOIP,CN,DIRECT`，为什么国内网站有时候还是莫名其妙走了海外节点？”

这涉及到了 **DNS 解析与 IP 分流的时间竞争关系**：
- 当一个域名进入分流引擎时，引擎首先尝试用域名规则去匹配；
- 如果域名规则没有命中，引擎必须知道这个域名的**实际公网 IP 是不是中国的（GEOIP,CN）**；
- 在传统的 `Redir-Host` 模式下，客户端必须先发起一次真正的 DNS 解析拿到 IP。如果本地 DNS 发生了污染，拿到的假 IP 不属于中国，分流引擎就会**误判其为海外资源而送入海外代理隧道**！

> [!IMPORTANT] 终极防泄漏解决方案
> 永远在客户端中开启 **`Fake-IP`** 增强模式，配合规范的 `geosite` 域名集规则。让分流在域名阶段就完成判定，彻底切断对本地不稳定 DNS 解析的依赖。同时在 IP 类分流规则末尾追加 `no-resolve` 参数（如 `GEOIP,CN,DIRECT,no-resolve`），强制阻止分流引擎对未命中域名的静默反向 DNS 查询。

## 模块七：分应用代理与特定程序进程分流技术

如果您是一名前端开发者、外服游戏玩家或多任务工作者，您可能希望实现更精细的控制：
- 仅让 Chrome 浏览器和 Git 终端走海外节点；
- 微信、飞书、钉钉、Steam 国区下载等软件强制 100% 物理直连，哪怕开启全局代理也不准碰它们。

### 1. 基于进程名（PROCESS-NAME）的分流规则
Mihomo 核心原生支持读取发起套接字的 Windows/macOS 进程名称：

```yaml
# 在 rules: 列表顶部加入进程分流规则
rules:
  # 强制办公协作软件走本地直连
  - PROCESS-NAME,WeChat.exe,DIRECT
  - PROCESS-NAME,Feishu.exe,DIRECT
  - PROCESS-NAME,DingTalk.exe,DIRECT
  - PROCESS-NAME,Steam.exe,DIRECT

  # 强制特定开发工具走海外代理
  - PROCESS-NAME,git.exe,PROXY
  - PROCESS-NAME,cursor.exe,PROXY
```

### 2. Android 客户端的「分应用代理」开关
在 Android 端的 **v2rayNG** 或 **Clash for Android** 中：
- 打开左侧设置，找到 **「分应用代理 (Per-App Proxy)」**；
- 勾选模式为 **“仅代理选中的应用”**；
- 仅勾选 Chrome、YouTube、Twitter、Telegram，其余国内 App 一概不勾选。这是手机端最省电、最省流量、最防封号的神仙配置。

## 模块八：8 大真实分流踩坑案例实录与复盘（RCA 全景）

真实生产环境中的分流冲突往往极为隐蔽。以下精选 8 个极具代表性的工业级实测案例，为您展示从一线现象、抓包取证、根因分析（RCA）到彻底根治的完整闭环。

### 案例 1：误开全局模式导致微信账号触发高危异地风控
- **背景与现象**：某外企商务在与客户交流时，为了翻墙查资料顺手开启了「Global 全局模式」。10 分钟后微信强制退出，提示“账号在境外异常 IP 登录，已被临时限制资金收付”；
- **抓包与取证**：Wireshark 显示全局模式强制将微信 PC 端发往深圳腾讯服务器的长连接心跳包路由至美国洛杉矶节点；
- **根因分析 (RCA)**：微信反欺诈系统检测到该账号在数分钟内从上海物理 IP 突变至美国数据中心机房 IP，直接触发了支付级风控模型；
- **复盘与根治**：立即切换回 **`Rule (规则模式)`**，并在规则顶部将 `DOMAIN-SUFFIX,qq.com,DIRECT` 确保处于优先层级，微信解除异常后未再复发。

### 案例 2：后台挂着迅雷/BT 下载导致机场数千 GB 流量数小时内耗尽封号
- **背景与现象**：大学生新买的 500GB 季度机场套餐，开机挂了一下午下载一部国内高清纪录片，傍晚时发现机场全红断网，登录后台显示已欠费封停；
- **抓包与取证**：BT 客户端在后台与全球数万个 P2P 对等节点建立了并发连接；
- **根因分析 (RCA)**：由于分流规则末尾的 `MATCH,PROXY` 兜底规则，所有发往海外对等节点的非国内 IP 全部被送入 IEPL 跨境专线，短短 3 小时跑干了 500GB 专线流量；
- **复盘与根治**：在规则中配置针对 BitTorrent 的强制直连或直接丢弃规则，并在进行大型下载前，主动使用直连模式。

### 案例 3：国内网站虽然直连，但 CDN 解析至海外导致打不开
- **背景与现象**：某网民访问国内知乎网站，图片加载异常缓慢，查看日志发现知乎图片 CDN 走了海外节点；
- **抓包与取证**：DNS 查询日志显示知乎域名被海外公共 DNS 解析到了北美边缘 CDN 节点；
- **根因分析 (RCA)**：本地 DNS 配置中缺少针对国内域名的直连解析器，导致海外 DNS 将国内用户调度到了海外机房；
- **复盘与根治**：在 DNS 配置中补充权威国内直连解析器（如 `223.5.5.5`），图片加载瞬时回落至本地 5ms。

### 案例 4：第三方规则集冲突导致全网彻底断网
- **背景与现象**：用户从某论坛导入了一份号称“全网最强 10 万条规则”的第三方规则集，导入后电脑彻底无法上网；
- **抓包与取证**：审查规则文件，发现作者错误地将 `DOMAIN-SUFFIX,cn,PROXY` 误写为了全量代理；
- **根因分析 (RCA)**：所有 `.cn` 结尾的国内根服务器请求被错误路由至代理节点，造成域名解析死锁；
- **复盘与根治**：剔除冗余低质规则集，恢复使用经过广泛验证的标准 Loyalsoldier 精简规则库。

### 案例 5：跨国企业视频会议 Zoom 频繁丢包卡顿
- **背景与现象**：某外企员工在参加 Zoom 跨国视频会议时，音频断断续续，视频画面频繁卡成马赛克；
- **抓包与取证**：抓包显示 Zoom 客户端的实时音视频流（UDP 报文）全部被代理客户端截获并打包进了 TCP 加密隧道；
- **根因分析 (RCA)**：实时音视频通讯对传输时延与抖动极度敏感。将原生的 UDP 报文塞入经过中转的 TCP 代理隧道，触发了严重的 TCP 队头阻塞（Head-of-Line Blocking）；
- **复盘与根治**：在分流规则中加入针对 Zoom 域名的直连规则，让实时音视频流量走本地优质宽带直连，会议画面立刻恢复 1080P 丝滑无卡顿。

### 案例 6：GitLab 私有内网服务器误走代理导致权限拒绝
- **背景与现象**：某程序员在公司内网执行 `git clone` 拉取企业内部代码仓库时，终端提示 `Connection refused`；
- **抓包与取证**：终端开启了 `HTTP_PROXY` 环境变量，导致发往内网域名 `gitlab.mycompany.com` 的请求全部被送入海外节点；
- **根因分析 (RCA)**：分流规则中缺少针对公司内部私有二级域名的 DIRECT 直连放行；
- **复盘与根治**：在规则文件顶部追加 `DOMAIN-SUFFIX,mycompany.com,DIRECT`，成功排除内网域名干扰。

### 案例 7：Steam 游戏更新下载速度被掐死在 200KB/s
- **背景与现象**：玩家在 Steam 平台下载百 GB 级 3A 游戏大作时，下载速度极慢且极其消耗机场专线配额；
- **抓包与取证**：Steam 的内容分发网络（CDN）节点被分流规则误判为海外资源，走了跨境代理；
- **根因分析 (RCA)**：分流规则库未针对游戏下载 CDN 进行分离，导致流量错配；
- **复盘与根治**：引入专门的 Steam 下载直连规则集，使游戏更新流量直连国内蒸汽平台与电信 CDN，下载速度瞬间跑满千兆宽带（110MB/s）。

### 案例 8：手机银行 App 启动反外挂 SDK 闪退
- **背景与现象**：某用户在手机开启 VPN 代理后，打开某国有大型银行手机 App，App 在启动白屏数秒后直接闪退；
- **抓包与取证**：App 内置的反洗钱反欺诈 SDK 在初始化阶段检测到底层存在虚拟网卡（`tun0`）；
- **根因分析 (RCA)**：银行金融客户端为防止注入攻击，默认严禁在存在全局 VPN 接口的环境下运行；
- **复盘与根治**：在移动端客户端开启「分应用代理」，将手机银行 App 显式排除在代理接管列表之外，App 恢复秒开。

## 模块九：经典 YAML 自定义分流规则编写实战指南

教您像专业网络工程师一样，在自己的配置文件中编写优雅、精准的分流逻辑：

### 3. 常见分流优先级陷阱与规避指南
在编写自定义分流规则时，必须牢记“**自上而下匹配，首次命中即终止**”的基本原则：
- **陷阱 1：兜底规则书写位置错误**。切勿将 `MATCH,PROXY` 或 `GEOIP,CN,DIRECT` 放在配置顶部。一旦把宽泛的兜底规则写在最前面，其下方的所有精细域名规则（如 OpenAI 走专线）将永远无法被匹配执行；
- **陷阱 2：缺少局域网内网放行**。必须永远在规则链的最顶端显式放行本地回环与私有地址（`127.0.0.1`、`192.168.0.0/16`、`10.0.0.0/8`），否则会导致局域网设备、路由器管理后台或本地开发服务无法连接；
- **陷阱 3：混淆关键字与后缀规则**。`DOMAIN-KEYWORD` 会执行模糊包含匹配（例如 `DOMAIN-KEYWORD,google,PROXY` 会导致包含该词汇的非 Google 域名也被代理），在生产环境中应尽量使用更严谨的 `DOMAIN-SUFFIX`。
rules:
  # 1. 本地回环与内网私有地址强制直连 (防止局域网打印机/路由器断连)
  - IP-CIDR,127.0.0.0/8,DIRECT,no-resolve
  - IP-CIDR,192.168.0.0/16,DIRECT,no-resolve
  - IP-CIDR,10.0.0.0/8,DIRECT,no-resolve

  # 2. 常见办公通讯与国内大厂服务直连白名单
  - DOMAIN-SUFFIX,weixin.qq.com,DIRECT
  - DOMAIN-SUFFIX,alipay.com,DIRECT
  - DOMAIN-SUFFIX,taobao.com,DIRECT
  - DOMAIN-SUFFIX,baidu.com,DIRECT

  # 3. 常见流媒体与 AI 工具定向分流策略组
  - DOMAIN-SUFFIX,openai.com,ChatGPT
  - DOMAIN-SUFFIX,anthropic.com,Claude
  - DOMAIN-SUFFIX,netflix.com,Netflix
  - DOMAIN-SUFFIX,youtube.com,YouTube

  # 4. GFW 常见封锁名单走主力代理节点
  - DOMAIN-SUFFIX,google.com,PROXY
  - DOMAIN-SUFFIX,github.com,PROXY
  - DOMAIN-SUFFIX,twitter.com,PROXY

  # 5. 国内地理 IP 强制直连
  - GEOIP,CN,DIRECT

  # 6. 最终兜底规则 (未命中的默认走向)
  - MATCH,PROXY
```

## 模块十：双平台自动化分流验证与自救脚本

### Windows 分流健康度与连通性验证脚本 (`check_routing.bat`)
新建批处理文件运行，一键测试分流引擎是否按照预期工作：

```bat
@echo off
chcp 65001 >nul
title 分流模式健康度与路径验证工具
echo ========================================================
echo  正在测试【国内直连分流】连通性 (测试目标: 百度)...
echo ========================================================
curl -I -s --connect-timeout 3 https://www.baidu.com | findstr "HTTP"
if %errorlevel% equ 0 (
    echo [√] 国内直连分流正常，未受阻断！
) else (
    echo [!] 警告：国内直连异常，可能误开了全局模式或本地网络受损！
)

echo.
echo ========================================================
echo  正在测试【海外代理分流】连通性 (测试目标: Google 204)...
echo ========================================================
curl -I -s --connect-timeout 5 http://www.gstatic.com/generate_204 | findstr "204"
if %errorlevel% equ 0 (
    echo [√] 海外代理分流正常，加密握手成功！
) else (
    echo [!] 警告：海外代理分流超时，请检查代理节点状态！
)

echo.
echo [√] 验证测试完毕。
pause
```
