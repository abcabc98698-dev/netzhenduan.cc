## 模块一：Android 平台网络代理虚拟化底座与接管机理

桌面操作系统（如 Windows 与 macOS）与移动端 Android 在代理接管上有本质区别。桌面端可以借助驱动签名直接注入虚拟网卡（Wintun）或篡改 WinINet 系统代理注册表，而 Android 操作系统基于严格的 Linux 命名空间（Network Namespace）与沙盒隔离机制，必须依托系统级的 `VpnService` API 建立通信隧道：

```
+─────────────────────────────────────────────────────────────────────────────+
|               v2rayNG 在 Android 操作系统中的流量调度微观时序图              |
+─────────────────────────────────────────────────────────────────────────────+
[各应用沙盒层]
  Chrome / Twitter / Telegram          微信 / 支付宝 / 招商银行
        │                                      │
        ▼ (TCP/UDP Socket 报文)                 ▼ (TCP/UDP Socket 报文)
┌─────────────────────────────────────────────────────────────────────────────┐
│ 操作系统内核网络层: Android VpnService 虚拟专用网隧道接口 (tun0, 10.0.0.2)     │
│  - 检查分应用代理包名过滤表 (Per-App UID Whitelist / Blacklist)               │
│  - 直连应用直接交由物理网卡 (wlan0 / rmnet_data0) 发送至本地基站              │
└──────────────────────────────────────┬──────────────────────────────────────┘

└──────────────────────────────────────┬──────────────────────────────────────┘
```

### 1. `VpnService` 的系统特权与流量拦截
当您在 v2rayNG 中点击右下角的“连接”浮动按钮时，Android 系统会弹出一个钥匙图标的安全授权确认框。在获得系统授权后：
- Android 系统服务 `ConnectivityService` 会动态创建一个名为 `tun0` 的虚拟网络适配器，并分配私有虚拟 IP 地址（通常为 `10.0.0.2/32`）；
- 系统的默认路由表会被强制改写，将所有应用出站的 IPv4 默认网关（`0.0.0.0/0`）直接重定向指向 `tun0` 设备；
- v2rayNG 进程通过底层系统调用的文件描述符（File Descriptor）读取 `tun0` 网卡中汇聚的原始三层数据包，交由嵌入的 Xray-core 内核处理；
- 在移动蜂窝网络（4G/5G）环境下，由于基站端通常设定了较为严苛的 MTU 阈值（典型为 1420 至 1500 字节），若代理数据流在经过 TLS 报文封装与协议头扩展后超出了链路最大传输单元，就会触发底层的 IP 报文分片（IP Fragmentation）。报文分片不仅会导致单包重传率大幅升高，还会急剧增加手机处理器的解包功耗。因此，在 v2rayNG 内部将虚拟网卡 MTU 合理调优（推荐设置为 1400 或 1280 字节）是保障移动端稳定性的重要基石。

### 2. 套接字保护机制（Socket Protection）与防环路死锁
若代理内核自身发往远端代理服务器（如香港或日本节点）的加密数据包也被重定向送回 `tun0`，网络协议栈就会发生不可逆的**自身嵌套递归与无限死锁（Infinite Loop）**，导致手机瞬间断网并严重发热。
- 为了避免这一物理灾难，Android 提供了特殊的系统调用 `VpnService.protect(int socket)`；
- v2rayNG 在创建与境外服务器握手的底层 TCP 套接字时，必须显式调用该 API 进行签名保护；
- 经过 `protect()` 保护的 Socket 流量将被操作系统绕过虚拟隧道，强制绑定至手机物理网卡（`wlan0` 或蜂窝数据网卡 `rmnet0`）直连发出。

## 模块二：Android 移动场景四大核心痛点深度剖析

移动设备与桌面电脑相比，面临着高度碎片化的硬件与更激进的电源管理策略。以下四大痛点是导致移动端体验断崖式下跌的元凶：

### 1. 国产深度定制系统的后台内存清剿（Low Memory Killer）
国产手机品牌（小米澎湃 HyperOS、华为鸿蒙 HarmonyOS、vivo OriginOS、OPPO ColorOS、荣耀 MagicOS）为了维持整机跑分与续航，内置了极具侵略性的内存管理和进程查杀守护进程。一旦手机熄屏超过 5 分钟，系统便会判定后台持续占用网络连接的 v2rayNG 为“异常耗电应用”，直接发送 `SIGKILL` 信号强杀后台 Core 进程，导致微信、Telegram、邮件即时消息彻底中断。为了保障进程存活，必须在各品牌系统设置中同时打通“自动启动权限”、“电池优化无限制白名单”、“后台锁定卡片”与“关联唤醒权限”四大核心关卡。

### 2. Android 9+ 私密 DNS（DNS-over-TLS）与 VpnService 冲突
Android 9.0 引入了全局「私密 DNS（Private DNS）」功能，强制将所有系统解析请求封装为 853 端口的 TLS 加密报文并发送至用户指定的解析器（如 `dns.google` 或腾讯云 `dot.pub`）。
- 当开启 v2rayNG 时，私密 DNS 请求往往由于无法被本地 tun2socks 正确解包，或因为境外 DoT 服务遭遇运营商物理拦截，导致全系统域名解析全面死锁；
- 手机通知栏频繁显示“已连接但无法访问互联网”，而所有海外与国内应用均陷入无网假死；
- 解决该冲突的最佳实践是将系统私密 DNS 设定为“关闭”，完全交由 v2rayNG 内部集成的国内与海外分流 DNS 引擎接管。

### 3. 分应用代理配置混乱导致的国内金融与政企办公拦截
许多用户习惯开启“全局路由”，导致在登录国内手机银行（招商银行、中国银行、工行）、个人所得税、交管 12123 以及企微钉钉时，国内服务端的反欺诈安全引擎检测到底层连接来自境外数据中心机房 IP，直接触发高危风险拦截，导致账号被临时冻结或强制人脸识别。必须依托精细化的「分应用代理（Per-App Proxy）」实现操作系统沙盒级的硬隔离。

### 4. 4G/5G 双栈蜂窝网络下的 IPv6 侧信道真实 IP 泄漏
国内三大运营商（中国电信、中国联通、中国移动）在移动蜂窝基站上已全量部署 IPv6。当手机通过 5G 上网时，如果 v2rayNG 未配置针对 IPv6 的拦截或路由分流，浏览器在访问同时支持 IPv4 与 IPv6 的海外站点时，会根据 RFC 6724 优先发起 IPv6 直连通信，直接绕过 IPv4 代理隧道，在目标服务器日志中赫然暴露您未经伪装的真实手机公网 IPv6 地址！

```
          ├── [否] ──► 核心启动失败或被杀。检查电池无限制设置与自动启动权限

                              ▼

          └── [设置正常] ──► 进入步骤 5
                              │
                              ▼
                【步骤 5: 检查 5G 蜂窝 IPv6 侧信道】
           在 WiFi 与 4G/5G 移动数据间切换对比
          ├── [WiFi 正常但 5G 断网] ──► 运营商 APN 仅分配 IPv6 或 IPv6 路由泄露。在设置中关闭 IPv6 路由
          └── [双网均断网] ──► 彻底清除 v2rayNG 应用数据并重新导入订阅链接
```

## 模块五：工程实战：基于 ADB 终端的 Android 代理运行体检脚本

对于进阶技术人员与网络工程师，当手机界面排查无法定位深层路由故障时，可通过 USB 连接电脑并启动 ADB（Android Debug Bridge）调试终端，运行以下 Shell 脚本秒级导出 Android 核心网络栈状态：

```bash
#!/bin/sh
# ==============================================================================
# netzhenduan.cc Android 移动端 v2rayNG 运行环境与 VpnService 诊断脚本
# 执行方式: adb shell sh /sdcard/diag_proxy.sh 或直接在 adb shell 中粘贴
# ==============================================================================

echo "=========================================================="
echo "    netzhenduan.cc Android v2rayNG 网络栈与环境体检"
echo "=========================================================="

# 1. 检查 v2rayNG 进程是否存活
echo "\n[1/5] 检查 v2rayNG 及其守护核心运行状态..."
V2_PID=$(pidof com.v2ray.ang)
if [ -n "$V2_PID" ]; then
    echo "  [OK] v2rayNG 前台/后台进程正常运行 (PID: $V2_PID)"
else
    echo "  [FAIL] 未检测到 com.v2ray.ang 进程！软件未运行或已被系统 LMK 强杀！"
fi

# 2. 检查 VpnService 虚拟网卡 (tun0) 状态
echo "\n[2/5] 探测系统底层 VpnService (tun0) 网络接口..."
TUN_INFO=$(ip addr show tun0 2>/dev/null)
if [ -n "$TUN_INFO" ]; then
    echo "  [OK] tun0 虚拟网卡已就绪:"
    echo "$TUN_INFO" | grep "inet " | awk '{print "       -> 虚拟 IP: " $2}'
else
    echo "  [FAIL] 未发现活动 tun0 接口！VpnService 未能成功接管系统路由！"
fi

# 3. 检查系统路由表默认网关指向
echo "\n[3/5] 审计操作系统 IPv4 路由表..."
ip route show | grep default | while read -r line; do
    echo "  [ROUTE] $line"
done

# 4. 检查 Android 全局私密 DNS (Private DNS) 状态
echo "\n[4/5] 检查系统 Private DNS 设置模式..."
DNS_MODE=$(settings get global private_dns_mode 2>/dev/null)
DNS_SPEC=$(settings get global private_dns_specifier 2>/dev/null)
echo "  [INFO] 当前私密 DNS 模式: ${DNS_MODE:-未配置/默认}"
if [ "$DNS_MODE" = "hostname" ]; then
    echo "  [WARN] 警告: 启用了特定私密 DNS 主机名 ($DNS_SPEC)！极易引发 VpnService 解析死锁！"
elif [ "$DNS_MODE" = "off" ]; then
    echo "  [OK] 私密 DNS 已关闭，由本地解析栈或代理核心统一托管。"
fi

# 5. 验证 DNS 域名解析响应速度
echo "\n[5/5] 测试移动端公共域名解析连通性..."
getprop net.dns1 2>/dev/null | awk '{print "  [LOCAL DNS 1] " $1}'
ping -c 1 -W 2 www.google.com >/dev/null 2>&1
if [ $? -eq 0 ]; then
    echo "  [PASS] 成功连通外网受限域名 (www.google.com)！"
else
    echo "  [FAIL] 无法连通外网目标，请排查节点可用性或分应用规则！"
fi

echo "\n======================= 移动端体检完毕 ======================="
```
