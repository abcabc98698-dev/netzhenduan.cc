# 评测方法论与质检标准

最后更新：2026年10月25日 ｜ 制定机构：网络诊断实验室技术审计委员会 ｜ 规范代号：NZD-SOP-NET-2026

## 一、评测方法论的核心哲学与测试原则

在复杂的跨国公网网络环境中，单次测量、非受控环境测速以及缺乏统计学样本的技术评测极易产生严重的“测量偏倚”（Measurement Bias）。网络服务商常常通过在闲时突发提速、针对常见测速平台配置伪造的虚假带宽白名单，或者在特定路由节点进行流量伪装，制造虚假的网络质量假象。

为彻底消除测试偏差，网络诊断实验室制定了严格的科学测试公理：

1. **确定性与可复现性（Reproducibility）**：所有测试用例必须具备精确的测试输入参数、清晰的物理拓扑路径描述与公开的开源探测代码。任何外部工程师按照相同规范在相同网络条件下执行测试，必须能够重现相同量级的测试结论。
2. **物理隔离与宿主机独占（Host Isolation）**：所有自动化探测探针均运行在独占硬件服务器上，绝不使用共享母机的低价虚拟化容器（如超售严重且容易受周边邻居干扰的 OpenVZ/LXC 容器），杜绝宿主机 CPU 调度抢占与虚拟网卡缓冲区溢出造成的假性丢包。
3. **时间序列全周期采样（Temporal Diversity）**：网络性能是高度时间敏感的物理过程。实验室规定任何评测结论必须覆盖连续 72 小时以上的连续采样数据，重点提取每日夜间 20:00 至 23:00（运营商骨干网流量最高峰、QoS 流量整形最严苛时段）的极值与稳态数据。
4. **统计学稳健性与离群值处理（Statistical Rigor）**：严禁采用单次 Ping 最小值代表节点延迟。实验室必须同时报告 RTT 均值（Mean）、中位数（Median）、95 分位数（P95）以及 RFC 3393 延迟抖动（Jitter）。

## 二、12 项工业级网络与服务质检核心指标

网络诊断实验室建立了涵盖传输层、路由层、应用层与系统运行态的 12 项工业级网络质检指标：

### 指标 1：三网晚高峰（20:00 - 23:00）吞吐量压测（Throughput Under Load）

- **定义与原理**：在电信、联通、移动三大运营商跨国流量峰值时段，利用多线程 TCP（`iperf3 -P 8 -w 2M`）以及单线程 HTTP/3（QUIC）连续向目标测速簇发起大文件拉取，持续时间不低于 60 秒。
- **量化标准**：
  - **卓越（Grade A）**：晚高峰可用吞吐量 $\ge 300\text{ Mbps}$，带宽波动系数 $\le 15\%$。
  - **良好（Grade B）**：晚高峰可用吞吐量在 $100\text{ Mbps} \sim 299\text{ Mbps}$ 之间。
  - **临界（Grade C）**：晚高峰可用吞吐量在 $30\text{ Mbps} \sim 99\text{ Mbps}$ 之间，出现轻微拥塞降速。
  - **不可用（Grade F）**：晚高峰吞吐断崖式下跌至 $30\text{ Mbps}$ 以下，无法维持 4K 超高清流媒体连续播放。

### 指标 2：TCP 丢包率与重传率（Packet Loss & Retransmission Rate）

- **定义与原理**：依据 RFC 2581（TCP 拥塞控制标准），通过 Linux 内核抓包统计在持续网络传输过程中发生 Fast Retransmit 与 RTO（Retransmission Timeout）重传报文占总报文的百分比。
- **量化标准**：
  - **极佳**：丢包率 $\le 0.10\%$，重传率 $\le 0.50\%$（专线级别物理直连）。
  - **正常**：丢包率在 $0.11\% \sim 1.00\%$ 之间，重传率 $\le 2.00\%$。
  - **严重恶化**：丢包率 $> 3.00\%$，重传率 $> 8.00\%$（触发丢包预警，TCP 拥塞窗口反复腰斩）。

### 指标 3：往返时延（RTT）中位数与 P95 分位数

- **定义与原理**：连续发送 1000 个探测包，记录每个报文的精确往返时间。统计序列中去除极端异常后的中位数（P50）与 95% 报文满足的最高时延（P95）。
- **量化标准**：中位数反映日常使用基线，P95 反映网络最恶劣波动时的真实体验。若 $\text{P95} - \text{P50} > 50\text{ ms}$，判定该链路存在严重的链路抢占与排队延迟（Bufferbloat）。

### 指标 4：延迟抖动（IPDV / Jitter，遵循 RFC 3393）

- **定义与原理**：按照 RFC 3393（IP Packet Delay Variation Metric）规范，计算连续到达两个探测报文的传输时延差的绝对值平均数。
- **量化公式**：
  $$\text{Jitter} = \frac{1}{N-1} \sum_{i=1}^{N-1} |(D_{i+1} - D_i)|$$
- **判定边界**：游戏专线要求 $\text{Jitter} \le 3.0\text{ ms}$；普通高清音视频通话要求 $\text{Jitter} \le 15.0\text{ ms}$；若 $\text{Jitter} > 30.0\text{ ms}$，用户将出现明显的语音卡顿与画面跳帧。

### 指标 5：BGP AS 路径跳数与穿透率（BGP Routing Efficiency）

- **定义与原理**：通过多视点 BGP Looking Glass 服务器审计数据流经自治系统（Autonomous System）的数量与路径跳数。
- **审计规则**：检查流量是否在跨国骨干网中绕道远端（如中国大陆发往香港的流量绕行美西洛杉矶或日本东京）。绕道跳数大于 2 个一级运营商的链路直接判定为路由劣化。

### 指标 6：跨境专线物理类型审计（IEPL/IPLC 真实性判定）

- **定义与原理**：验证服务商声称的“内网专线”是否为真正的物理层/数据链路层二层点对点专线（IEPL - International Ethernet Private Line），抑或是通过公网多跳中转伪装的“伪专线”。
- **测试方法**：
  1. 通过发送带有反向探测特征的 UDP/ICMP 探测序列，测量入口机房至落地机房的物理传输时延；
  2. 若深港专线时延 $< 5.5\text{ ms}$ 且在公网大面积海缆中断时零波动，判定为真实 IEPL 物理专线；若时延 $> 18\text{ ms}$ 且伴随公网路由抖动，判定为公网隧道伪装。

### 指标 7：原生住宅 IP 与广播机房 IP 属性审计（IP Type & Subnet Audit）

- **定义与原理**：检查节点落地公网 IP 地址的注册机构（RIR: ARIN/RIPE/APNIC）原始分配记录。
- **判定标准**：
  - **原生住宅 IP（Residential Native）**：IP 注册国家与实际 BGP 物理广播机房国家一致，且 ASN 类别为 ISP/Residential。
  - **广播机房 IP（Hosting Broadcast）**：IP 原始注册地在别国，通过 BGP 跨国宣告广播至目标机房，且 ASN 类别为 Hosting/DataCenter。

### 指标 8：IP 欺诈度评分（Fraud Score / Risk Score）

- **定义与原理**：整合全球顶级商业风控数据库（Scamalytics、IPinfo、MaxMind minFraud、Cloudflare Threat Score），对 IP 的历史滥用记录、爬虫活动与恶意代理行为进行综合风险评估。
- **量化分级**：
  - **0 - 15 分（纯净低风控）**：无任何滥用记录，顺利通行所有风控验证码。
  - **16 - 45 分（中度风控）**：偶有搜索引擎爬虫标记，触发普通图片验证码。
  - **46 - 100 分（高危黑名单）**：已被主流支付网关与平台标记为恶意代理，直接封禁。

### 指标 9：主流流媒体与顶尖 AI 平台解锁率

- **定义与原理**：自动化探针每隔 30 分钟模拟标准客户端向全球主要版权流媒体平台及主流大语言模型 API 发起内容请求。
- **审计矩阵覆盖**：
  - **流媒体平台**：Netflix（全区原创与非自制剧集）、Disney+、YouTube Premium、Amazon Prime Video、HBO Max。
  - **AI 计算平台**：OpenAI（ChatGPT Web 访问与 API 接口调用）、Anthropic Claude（全流程注册与对齐会话风控审计）、Google Gemini。

### 指标 10：TLS 1.3 密码套件握手成功率与 ALPN 协商健壮性

- **定义与原理**：利用自动化 TLS 探测客户端向目标代理中继发起握手测试，审计其支持的 Cipher Suites（AES-128-GCM、AES-256-GCM、CHACHA20-POLY1305）以及应用层协议协商（ALPN: `h2`, `http/1.1`）。
- **判定标准**：要求 100% 握手成功率；若由于服务端 OpenSSL 配置错误导致 ALPN 回落超时或直接返回 `unrecognized_name`，判定该节点协议栈存在工程缺陷。

### 指标 11：协议伪装特征逆向与抗主动探测健壮性

- **定义与原理**：利用模拟 GFW 主动嗅探探测机向节点端口发送畸形 HTTP 请求、无指纹 TCP 报文及重放 Client Hello 报文。
- **判定标准**：
  - 节点必须严格遵循对应协议的抗探测行为规范（如 VLESS-Reality 必须精准将非认证流量重定向至指定的真实合规 SNI 证书目标服务器，且 TLS 证书指纹必须与真实服务器完全吻合）。
  - 若节点在遭遇未知报文时直接静默切断连接或返回非标准的错误响应，判定其存在被指纹特征库捕获的风险。

### 指标 12：客户端长时间运行系统内耗监测（72 小时压力审计）

- **定义与原理**：在标准 Windows 11 与 macOS 硬件环境下连续运行代理客户端 72 小时，承载不低于 500GB 的连续并发流量。
- **监视指标**：
  - 物理内存驻留集（RSS）增量（验证是否存在 Go 垃圾回收停滞或 C 内存泄漏）；
  - 线程句柄数与系统套接字释放情况；
  - Wintun 虚拟网卡驱动在高并发瞬时断流时的自愈时间与死锁几率。

## 三、标准化测试作业流程（SOP 执行规程）

网络诊断实验室的每一次质量审计与横评发布，均遵循严格的六步 SOP 作业流程：

```
[步骤 1: 探针初始化] ---> [步骤 2: 基准线对齐] ---> [步骤 3: 72小时连续采样]
        |
[步骤 6: 报告发布] <--- [步骤 5: 专家同行评审] <--- [步骤 4: 离群数据清洗]
```

1. **探针环境初始化**：清空测试宿主机的临时缓存与网络连接池，重启网络驱动，确认系统时间通过 PTP（Precision Time Protocol）或高精度 NTP 同步至微秒级精度。
2. **基准物理线对齐**：使用官方权威回显源测量宿主机至国际海底光缆登陆站的当前物理基准延迟，记录当天海缆突发跳纤或维修事件。
3. **连续压力采样**：自动化测试守护进程启动，每隔 5 分钟执行一次连通性与握手审计，每隔 60 分钟执行一次 iperf3 多线程带宽测试，每日晚高峰 20:00 - 23:00 启动 100Mbps 饱和度对抗压测。
4. **离群数据清洗**：剔除由测试宿主机所在本地机房电源故障等外部不可控因素导致的单点异常，采用四分位距法（IQR: Interquartile Range）清除统计噪点。
5. **专家同行评审**：由首席网络架构师与传输安全工程师对清洗后的数据进行交叉核对，重点核查丢包率异常与专线穿透真实性。
6. **签名与版本发布**：生成带哈希时间戳的测试报告并公开上架，明确标注测试工具版本与 `dataStatus` 状态。

## 四、数据状态（dataStatus）评级与生命周期管理

互联网基础设施动态变化极为迅速。为防止过期评测误导用户，网络诊断实验室在所有横评与节点评测页面中引入统一的 `dataStatus` 元数据体系：

- **`ACTIVE_VERIFIED`（现行可信）**：测试数据采集于最近 30 天以内，且最近 24 小时的自动化探针巡检未报告任何重大链路降级。
- **`OBSOLETE_DEPRECATED`（待更新重测）**：测试数据超过 60 天未执行全量 72 小时压测，仅作为历史参考，实验室将在本季度内安排复测排期。
- **`ANOMALY_WARNING`（异常告警）**：自动化巡检系统在最近连续 3 个采样周期内检测到骨干网丢包率超过 10% 或流媒体大面积失效，已在页面显著位置悬挂黄牌警告。
- **`RISK_ALERT`（高危风险退市）**：服务商发生严重违约、技术蜜罐嗅探证据确凿、恶意虚标或跑路停机，永久列入实验室风险黑名单。

## 五、同行评审、数据质疑与复测申诉机制

网络诊断实验室坚信科学评测应接受行业与社区的共同监督。

若任何服务提供商或技术同行对本实验室发布的数据存在异议，可准备详实的抓包 PCAP 文件、时间戳对齐日志及服务器配置清单，发送邮件至 `audit@netzhenduan.cc` 发起复测申诉。实验室技术委员会将在 5 个工作日内调取历史原始日志，与申诉方共同进行实时复测验证，并在核实无误后 24 小时内完成官方勘误发布。
